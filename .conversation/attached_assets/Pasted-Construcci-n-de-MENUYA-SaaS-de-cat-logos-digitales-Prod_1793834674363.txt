Construcción de MENUYA — SaaS de catálogos digitales

Producto de Atom Labs

Actúa como un equipo senior de desarrollo de software compuesto por arquitectos de software, desarrolladores frontend y backend, diseñadores UX/UI y especialistas en productos SaaS.

Quiero que construyas una aplicación web funcional llamada MENUYA, propiedad de Atom Labs.

No quiero solamente una landing page ni un prototipo visual. Quiero una primera versión funcional de un SaaS que permita a los negocios crear, administrar y publicar sus propios catálogos digitales y recibir pedidos directamente desde ellos.

IMPORTANTE: comienza inspeccionando el proyecto existente. Si ya hay código funcional, consérvalo y trabaja sobre él. No destruyas ni reconstruyas innecesariamente componentes que ya estén bien implementados.

No te limites a explicar cómo lo harías. Ejecuta la implementación directamente.

⸻

1. Visión del producto

MENUYA será una plataforma SaaS de catálogos digitales para comercios.

El sistema debe permitir que cualquier negocio cree su espacio, personalice su catálogo, agregue productos, configure sus métodos de pago y reciba pedidos.

El producto estará dirigido inicialmente al mercado colombiano, pero su arquitectura debe permitir crecer a otros países.

No debe estar limitado a restaurantes. Debe funcionar para:

* Restaurantes.
* Comidas rápidas.
* Cafeterías.
* Panaderías.
* Tiendas de ropa.
* Zapaterías.
* Ferreterías.
* Tiendas de tecnología.
* Barberías.
* Salones de belleza.
* Comercios generales.

La plataforma debe tener una arquitectura escalable y modular.

2. Identidad visual y experiencia de usuario

Este punto es prioritario.

Quiero que MENUYA tenga una identidad visual propia, moderna, premium y reconocible.

NO quiero una interfaz genérica de SaaS generada con plantillas de inteligencia artificial.

Evita los dashboards convencionales que parecen copias de cualquier plantilla administrativa.

Diseña una experiencia con:

* Personalidad visual.
* Jerarquía tipográfica bien trabajada.
* Espacios y proporciones equilibradas.
* Componentes con identidad propia.
* Microinteracciones elegantes.
* Animaciones sutiles.
* Transiciones fluidas.
* Iconografía consistente.
* Excelente experiencia móvil y escritorio.

La marca MENUYA debe sentirse como un producto tecnológico profesional desarrollado por Atom Labs.

La identidad de MENUYA debe ser independiente de la personalización que cada comercio pueda aplicar a su propio catálogo.

Los catálogos públicos de los negocios deben poder tener estilos diferentes sin perder la calidad de experiencia de la plataforma.

No abuses de gradientes, sombras, tarjetas repetitivas ni elementos decorativos innecesarios.

3. Arquitectura técnica

Utiliza una arquitectura moderna y organizada.

Tecnologías preferidas:

* React.
* TypeScript.
* Vite.
* Tailwind CSS.
* Lucide Icons.
* Componentes reutilizables.
* Arquitectura modular.
* Manejo centralizado de estados cuando sea necesario.

Por ahora, NO integres Supabase, Firebase ni servicios externos que requieran credenciales.

La aplicación debe poder ejecutarse inmediatamente en Replit.

Utiliza almacenamiento local persistente mediante localStorage o IndexedDB para esta primera versión.

Crea una capa de servicios y repositorios independiente de la interfaz para que posteriormente podamos conectar una base de datos real sin tener que reescribir toda la aplicación.

Organiza el código para facilitar futuras integraciones de:

* Base de datos PostgreSQL.
* Autenticación real.
* Almacenamiento de imágenes.
* Pasarelas de pago.
* Notificaciones.
* Correos electrónicos.
* Dominios personalizados.

IMPORTANTE: esta versión es una demostración funcional local. No presentes el almacenamiento local como una solución de producción multiusuario ni como un sistema seguro de autenticación.

4. Modelo de negocio y estructura SaaS

MENUYA debe funcionar bajo un modelo multiempresa.

Debe existir un SUPER ADMINISTRADOR, que será el administrador central de toda la plataforma.

El Super Admin podrá:

* Crear negocios.
* Aprobar solicitudes de registro.
* Suspender negocios.
* Activar negocios.
* Consultar usuarios.
* Administrar planes.
* Consultar suscripciones.
* Configurar precios.
* Consultar estadísticas generales.
* Revisar actividad de la plataforma.
* Configurar parámetros generales.

Cada negocio tendrá su propio espacio de administración.

Los datos de cada comercio deben estar separados lógicamente mediante identificadores de negocio, preparando la arquitectura para aislamiento real de datos cuando se conecte el backend definitivo.

5. Sistema de dominios y direcciones

Utiliza un único dominio principal para todos los negocios.

Ejemplo:

* menuya.com/mitienda
* menuya.com/elsabor
* menuya.com/ropasofia

No crear subdominios individuales para cada negocio.

No implementar direcciones como mitienda.menuya.com.

Las rutas administrativas estarán dentro del mismo dominio:

* menuya.com/app
* menuya.com/admin

Los catálogos públicos deben resolverse dinámicamente mediante el slug del negocio.

Las rutas institucionales y administrativas deben tener prioridad sobre la resolución dinámica de slugs para evitar conflictos.

Deja preparada una futura funcionalidad de dominios personalizados como característica de un plan superior.

1. Registro automático.
2. Registro con aprobación manual.

Si se requiere aprobación, el negocio debe quedar pendiente hasta que el administrador lo autorice.

Implementa una sesión de demostración y rutas protegidas a nivel de interfaz.

Crea un acceso de demostración para el administrador central:

Correo: admin@menuya.com
Contraseña: MenuyaDemo2026!

Estas credenciales son exclusivamente para desarrollo y demostración. No deben considerarse credenciales seguras para producción.

13. Sistema de carrito y pedidos internos

No quiero que el sistema se limite a redirigir al usuario a WhatsApp.

MENUYA debe tener un proceso interno de pedidos.

El cliente podrá:

1. Entrar al catálogo.
2. Seleccionar productos.
3. Elegir variantes y complementos.
4. Agregar productos al carrito.
5. Modificar cantidades.
6. Consultar el total.
7. Continuar al checkout.
8. Ingresar sus datos.
9. Confirmar el pedido.

Datos del cliente:

* Nombre.
* Teléfono.
* Modalidad de entrega.
* Dirección cuando corresponda.
* Observaciones.
* Método de pago.

Modalidades:

* Domicilio.
* Recoger en el establecimiento.

Métodos de pago iniciales:

* Efectivo.
* Transferencia bancaria.
* Pago al recoger.
* Otros métodos configurados por el negocio.

No integrar pasarelas de pago todavía.

Al confirmar, el pedido debe quedar registrado y aparecer en el panel del negocio.

El cliente no necesita crear una cuenta para realizar un pedido.

Cada negocio debe tener una numeración de pedidos independiente.

24. Instrucción final

Construye MENUYA como un producto SaaS real en su experiencia y arquitectura, no como una simple página de presentación.

Prioriza una interfaz original, elegante y profesional.

No copies literalmente el diseño de otras plataformas. Puedes tomar como referencia funcional plataformas de catálogos digitales como OlaClick, pero MENUYA debe tener su propia identidad visual y experiencia.

No integres servicios externos ni solicites credenciales en esta etapa.

No te detengas a hacer preguntas innecesarias.

Primero inspecciona el proyecto, después implementa, ejecuta y corrige los errores.

Al terminar, verifica que las rutas principales funcionen, que los datos persistan localmente y que el recorrido completo de un cliente —desde abrir un catálogo hasta confirmar un pedido— funcione correctamente.

El resultado debe ser una primera versión navegable y funcional de MENUYA, de Atom Labs.
